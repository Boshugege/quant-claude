# 进益资本杯 · 本地因子评分工具包

用官方公开的 30 分钟 bar 数据，按平台的评测流程（官方标签 + 官方风格剔除）在本地计算五项评分指标：

- IC 均值
- IC_IR
- 多空夏普
- 压力场景稳定性
- 换手率

候选因子可以先在本地筛一遍，再决定哪些值得提交到平台。

> 本包不含数据，`data/` 只是占位目录。行情请按下文“1. 准备数据”下载；官方风格暴露和代码对照表不分发，没有它们时本地评估不做风格和行业剔除（见第 4 节）。

---

## 0. 环境

需要 Python 3.8 或更高版本：

```bash
pip install -r requirements.txt
```

依赖只有 numpy、pandas 和 pyarrow（用于读取 feather 文件）。数据区间越长，占用内存越大；跑多年全量或多进程并行时，建议使用大内存机器。

## 1. 准备数据（占位 → 下载）

| 项目 | 内容 |
|---|---|
| 数据 | 比赛方公开的 30 分钟 bar，`cpt_jyc_2026_e2e_bar30m` |
| 下载链接 | <https://bigquant-public-download.tos-cn-shanghai.volces.com/jyc2026/cpt_jyc_2026_e2e_bar30m.tar.gz> |
| 解压后 | `cpt_jyc_2026_e2e_bar30m/YYYYMM.0.feather`，2020-01 至 2024-12，每月一个文件，约 500 MB |
| 默认位置（占位） | `data/cpt_jyc_2026_e2e_bar30m/` |

用脚本下载，会自动解压并修正文件权限：

```bash
bash download_data.sh
```

也可以手动下载。如果数据放在别处，用环境变量指定位置：

```bash
export JYC_BAR30M_DIR=/你的路径/cpt_jyc_2026_e2e_bar30m
```

压缩包里文件的权限位不规范，有的不可读。手动解压后请执行一次：

```bash
chmod 644 cpt_jyc_2026_e2e_bar30m/*
```

同一地址下还有其他粒度的数据。本工具只用 30 分钟数据，下面的链接仅供参考：

- 1 分钟：<https://bigquant-public-download.tos-cn-shanghai.volces.com/jyc2026/cpt_jyc_2026_e2e_bar1m.tar.gz>
- 5 分钟：<https://bigquant-public-download.tos-cn-shanghai.volces.com/jyc2026/cpt_jyc_2026_e2e_bar5m.tar.gz>
- 15 分钟：<https://bigquant-public-download.tos-cn-shanghai.volces.com/jyc2026/cpt_jyc_2026_e2e_bar15m.tar.gz>

**数据要点**

- 每天 9 根 bar：09:25（集合竞价）、10:00、10:30、11:00、11:30、13:30、14:00、14:30、15:00。本地 09:25 竞价 bar 对应平台的 09:30 截面，其余 7 个截面一一对应。
- 价格和成交额的单位是“分”，读入时已除以 100。OHLC 缺失记为 −1，读入时已转为 NaN。
- 只有 3 档盘口，而平台有 5 档。
- 本地数据没有 `pre_close`，用前一交易日 15:00 收盘价按复权因子换算得到。
- **数据清洗**：一根 bar 的 VWAP 必须落在 [最低价 × 0.98, 最高价 × 1.02] 之内，否则视为无效。2021 年约有 0.19% 的 bar 不满足，多为 15:00 bar，疑似计入了盘后或大宗成交。无效 bar 不参与任何 VWAP 累加（`amount_c` / `volume_c`），它的标签记为缺失。

## 2. 快速开始

```bash
python3 run.py --start 2024-01 --end 2024-12
```

这条命令会评估 `factor_lib.FACTORS` 中的全部因子，输出终端表格，并在 `结果/` 下生成 CSV 和 Markdown 文件。常用参数：

| 参数 | 作用 |
|---|---|
| `--start / --end` | 数据区间（按月，含两端），默认 2023-01 至 2024-12 |
| `--only E1 E2` | 只评估指定编号。已填公榜分数的因子仍会一起参与排名 |

评估自己写的候选因子，可以参考示例脚本：

```bash
python3 example_custom_factor.py --jobs 8
```

## 3. 标签（官方定义，已逐行核实）

平台的官方标签表 `cpt_jyc_2026_vwap` 里每行有 `vwap_return`、`vwap`、`end_price` 等字段，逐行核实结果：

```
vwap_return = end_price / vwap − 1，窗口为截面之后的 30 分钟 (t, t+30]
```

也就是在截面之后 30 分钟内按 VWAP 买入，在这 30 分钟结束时按收盘价卖出。11:30 截面对应 13:00–13:30；**14:30 截面对应 14:30–15:00，同一交易日，有标签**。

- 本地实现 `y_off`：下一根 30 分钟 bar 的 收盘价 ÷ 清洗后 VWAP − 1，与官方标签的截面秩相关约 0.97。平台用更细的数据计算，本地无法逐笔复现。
- 如果有用 1 分钟数据重建的标签缓存，放到 `data/labels_y_off.parquet`（或用环境变量 `JYC_LABEL_CACHE` 指定），会优先使用。
- 官方 VWAP 同样不含异常成交，与本地清洗规则的效果一致。

## 4. 五项指标的本地实现（`localeval.evaluate`，与平台流程一致）

平台的处理顺序是：inf 处理 → 去极值 → 标准化 → 风格剔除（取残差）→ 计算指标。本地的做法：

| 步骤 / 指标 | 本地实现 |
|---|---|
| 因子处理 | 因子缺失补 0；逐截面标准化后，对当日 10 个官方风格暴露（SIZE、BETA、MOMENTUM、RESVOL、SIZENL、BTOP、LIQUIDTY、EARNYILD、GROWTH、LEVERAGE）和 32 个申万一级行业哑变量做 OLS（含截距），取残差；这样处理后与平台处理后的因子值相关 1.000000。没有官方暴露的股票不参与评估。去极值对秩类指标几乎没有影响，不做 |
| IC 均值 | 残差因子与标签的截面 Spearman 秩相关（至少 100 只股票），对所有截面求平均 |
| IC_IR | IC 序列的均值 ÷ 标准差 |
| 多空夏普 | 每个截面取残差因子前 10% 减后 10% 的等权标签收益，年化：均值 ÷ 标准差 × √(242 × 8) |
| 压力稳定性 | 按截面标签离散度（截面标准差）的中位数分高、低两组，取较弱一组的 IC_IR |
| 换手率 | 多头（前 10%）和空头（后 10%）两腿，在**同一交易日内**相邻截面之间被替换的成分占比，跨日那一次不计；两腿取平均 |

**风格暴露数据**：`localeval.py` 从 `data/exposure/`（或环境变量 `JYC_EXPOSURE_DIR` 指定的目录）读两类文件：按年保存的官方风格暴露 `exposure_YYYY.parquet`（内容对应平台表 `cpt_jyc_2026_exposure`），以及代码对照表 `id_map.csv`。官方风格暴露表按真实代码索引，本地行情使用主办方的匿名代码，所以两类文件缺一不可。**这两类文件都不随本包分发，对照表也不随仓库发布。** 缺少它们时程序会给出提示，并退回不剔除风格和行业：五项指标仍能算出，但与平台口径不一致，下面“与平台的一致程度”里的误差范围不再适用。

**与平台的一致程度**：拿平台导出的因子值，用本地评测计算，和平台自测相比（2024-01-02 至 03-01，5 个因子）：
- IC 均值误差约 0.001–0.002，IC_IR、压力误差约 0.01–0.04，换手误差约 0.001；
- 剩余差异来自本地标签（与官方的截面秩相关约 0.97）；用官方标签计算时，误差在 0.003 以内。

**本地综合分**：在本地因子池内，对五项分别做百分位排名（换手率越低排名越高），各占 20%，与官方规则一致。本地池子与平台的全体提交不同，所以本地综合分只适合比较你自己的因子之间的相对好坏。

## 5. 新增因子

在 `factor_lib.py` 的 `FACTORS` 中添加一行：

```python
("编号", "名称", 公榜分数或None, lambda p: 计算函数(p), "备注")
```

- 输入 `p` 是面板，每行是一只股票的一根 30 分钟 bar，已按“股票、时间”排序。函数返回与 `p` 行对齐的 Series，值越大表示越看多。
- **只能使用当前及过去的数据**，例如 `groupby("instrument_id").shift(1)` 或滚动窗口。严禁使用标签列（`y_*`、`next_vwap`）。

**面板字段**

| 类别 | 字段 |
|---|---|
| 原始数据 | `open/high/low/close/volume/amount/deal_number`、`bid/ask_price1-3`、`bid/ask_volume1-3`、`bid/ask_num_orders1-3`、`adjust_factor` |
| 键 | `instrument_id`、`date`（bar 结束时刻）、`day`（交易日）、`slot`（HHMM，09:25 bar 记为 930） |
| 价格 | `px`（bar 末中间价，盘口无效时用收盘价）、`vwap_w`（本 bar 清洗后的 VWAP）、`pre_close`（推导出的昨收） |
| 清洗后量额 | `amount_c`、`volume_c` |
| `add_components` 中间量 | `day_vwap`、`prev_px`、`sigma`（40 窗口收益标准差）、`r_day`、`r_30`、`r_vw`、`r_dvwap`、`r_rng`、`cnt_sum` |

**工具函数**

- `grolling(s, keys, window, fn, min_periods)`：快速的分组滚动计算。
- `rank_blend(p, cols, weights)`：把多个分量在截面内居中排名后加权平均。

## 6. 防过拟合（`research.py`）

1. **时间切分**：
   - 开发集 2020–2022：用于探索和调参；
   - 验证集 2023：用于挑选候选；
   - 保留集 2024：只在最终确认时用一次。
2. **入选条件**：候选必须在开发集和验证集上同时优于基准。
3. **固定参照池**：每个候选都单独放进固定参照池（`FACTORS` 中的全部因子）计算百分位，候选之间互不影响，结果可以复现。参照池的指标缓存在 `结果/缓存/`。**修改 `FACTORS` 之后要删除这个缓存。**
4. **少调参**：只尝试有经济含义的结构变化，不做网格搜索。

调用方式：

```python
research.evaluate_candidates({名称: 函数}, splits=("开发", "验证"), n_jobs=8)
```

函数返回每个候选在各切分上的五项原始指标和综合分。`n_jobs > 1` 时用 fork 多进程，子进程共享面板内存。在多核机器上，建议设置 `OMP_NUM_THREADS=1`，避免线程数过多、互相争抢 CPU。

## 7. 局限

1. **盘口和委托笔数类因子只是近似**。平台是 30 分钟内逐分钟取均值、用 5 档；本地只有 bar 末快照和 3 档。这类因子在 `FACTORS` 中标为 `approx`。
2. **需要分钟内信息的因子无法用 30 分钟数据复现**，例如分钟收益偏度、分钟价量相关。这类因子需要另外下载 1 分钟数据。
3. **本地池子与平台池子不同**，本地综合分只用于相对比较。
4. **平台的 1 分钟数据没有 09:30:00 这根 bar**（09:25 集合竞价之后直接是 09:31）。平台因子代码如果按“时间等于窗口终点”取 09:30 窗口的末价，会取不到值，09:30 截面就没有信号；本地 30 分钟数据的 09:25 bar 有值，所以本地看不出这个问题。写平台代码时，09:30 窗口请取 09:25 竞价 bar。
5. **本地因子值不一定等于平台因子值**：本地用 30 分钟数据近似，平台代码用 1 分钟数据，股票特征类分量的口径可能不同。重要候选请以平台代码的计算结果为准。
6. **本地数据是 2020–2024 年**，和公榜、私榜的评估区间不重叠，本地结果更接近真正的样本外表现。
