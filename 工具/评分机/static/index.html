任务

赋分表

按平台的赋分规则排名：五项指标各自在本表全部因子中的百分位，等权平均（换手越低越好）。总体 = 参照池（有公榜分的平台代码因子）+ 区间覆盖赋分窗口的全部已完成任务。同名任务只保留最新一次。总体只有我们自己的因子，头部比公榜更拥挤，分差会被放大；它用来衡量进步、找短板，不是公榜分的估计。公榜估计另列：取指标最接近的几个同快照锚点（参照池里同一时刻抄下公榜分的因子），加上指标差 × 边际价值（换手、IC 均值全额，IC_IR、压力减半，多空夏普不计）。本地换手、IC 均值几乎 1:1 搬到公榜，IC_IR、压力只能粗排；头部之间差距小于下面的“头部误差”时应视为持平；标“外推”的因子指标落在锚点范围之外（例如换手远低于所有锚点），估计只能当方向参考。判断两个相近因子谁更好，请看任务里的配对比较。

参照池

有公榜分数的因子，用实际提交到平台的代码在评分机上按平台方式运行后评分（2026-10-11 起；此前用 factor_lib 的 30 分钟面板复刻，头部校准失效）。估计公榜分只用“校准”列打勾的同一时间快照拟合。任务结果里的“百分位”“估计公榜分”都相对这个池子计算；比较相近的候选请看配对比较。

这台评分机做什么

按比赛平台 jyc_eval 的同一流程，给一个因子算出五项原始指标和完整诊断。口径已用平台导出的数据逐项核实（见仓库 e2e/reports/12、本地评分系统说明.md）。

评分口径（与平台一致）

  • 标签：截面之后 30 分钟窗口 (t, t+30] 的收盘价 ÷ 同窗口 VWAP − 1；11:30 对应 13:00–13:30，14:30 对应 14:30–15:00。默认用本地由 1 分钟数据重建的标签（与官方截面秩相关约 0.97）；选“官方标签片段”时只评估平台导出过的区间（2021-06、2024-01-02~03-01）。
  • 因子处理：每个截面 inf / 缺失补 0 → 标准化 → 对当日 10 个官方风格和 32 个申万一级行业哑变量（含截距）回归取残差；没有官方暴露的股票不参与评估。
  • IC：残差与标签的截面 Spearman 秩相关；IC_IR = 均值 ÷ 标准差。多空夏普：前 10% 减后 10% 的等权标签收益，按 √(242×8) 年化。
  • 压力稳定性：按截面标签离散度中位数分高低两组，取较弱一组的 IC_IR。换手：多空两腿在同一交易日内相邻截面的成分替换比例，跨日不计。

能提交什么

类型上传什么怎么运行
传统因子提交平台上传用的 .ipynb 或 .py（定义 main(datasources, start_date, end_date)）在模拟平台上原样运行：import dai 指向本地 DuckDB 0.9.2（与平台同版本），SQL 不做任何改写；自测单元（含 jyc_eval）自动跳过
端到端提交Transformer_modelsave_train.py + Transformer_modelsave_predict.ipynb + transformer_model.json，或三者的 zip运行推理 notebook 的 main（CPU torch），不训练
因子值文件parquet / csv，三列 date, instrument, factor代码可以是真实代码（6 位数字加交易所后缀）或伪代码（ID 加 4 位数字）；09:25 视为 09:30
研究脚本.py，定义 factor(panel)，返回与 panel 等长的数组panel 是 localeval.build_panel 的结果（30 分钟 bar 加 factor_lib 中间量），按年分块计算，每块预热 6 个月
已登记因子不上传，填 factor_lib 编号同研究脚本
SQL.sql，一条 DuckDB 查询，返回三列可直接引用平台表名，例如 cpt_jyc_2026_stock_bar1m

模拟平台的数据表

  • cpt_jyc_2026_stock_bar1m：1 分钟行情，单位元，OHLC 缺失为 NULL，含 pre_close（前一交易日收盘按复权因子换算）、adjust_factor、instrument_id、instrument（能映射的用真实代码，其余为 ID 伪代码）。本地只有 3 档盘口，4–5 档为 NULL，用到 4–5 档的代码会得到提示。
  • all_instruments、cpt_jyc_2026_instruments（股票池：当日有行情的股票 × 8 个截面）、cpt_jyc_2026_vwap（本地重建的标签）、cpt_jyc_2026_exposure（官方风格暴露）。
  • filters={"date": [开始, 结束]} 与平台相同；只给日期的结束日包含当天全天。没有 5 / 15 / 30 分钟表。

平台规则检查

平台型提交会检查：是否恰好三列 date, instrument, factor；时间是否都在 8 个截面（09:30 … 14:30）；有无重复键、inf；每个截面相对股票池的缺失率是否超过 40%（平台超过会静默出错）。内存超过 30 GB 或运行超过 3 小时的任务会被终止（与平台一致）。

结果怎么读

  • 五项指标是平台口径的原始值；“不剔除风格”一列只作对照，差距大说明因子的收益有很多来自风格或行业。
  • 参照池百分位：在 factor_lib 中有公榜分数的因子里排第几（同区间同口径）。估计公榜分由参照池的“本地综合分 → 公榜分”线性拟合得到，只是粗略近似：平台分数是全体提交中的排名，会随别人提交而变。
  • 分截面里某个截面“常数 / 全 0”很多，通常是 SQL 在那个截面取不到数据（例如 1 分钟数据没有 09:30:00 这根 bar，按窗口终点取末价会得到 0）。
  • 本地与平台的已知差异：标签是本地重建的（约 0.97）；只有 3 档盘口；股票池是“当日有行情的股票”，与平台的中证 1000 历史成分可能略有出入。

API

服务只监听远端的 127.0.0.1。本机先建隧道：

ssh -N -L 46220:127.0.0.1:46220 personal

之后用 http://127.0.0.1:46220 访问。自动生成的交互文档在 /docs。

Python 示例

import requests
r = requests.post("http://127.0.0.1:46220/api/jobs", params={"wait": "true"},
                  files=[("files", open("my_factor.ipynb", "rb"))], data={"start": "2023-01", "end": "2024-12"})
res = r.json()["result"]
print(res["metrics"], res["reference_pool"]["estimated_public_score"])
