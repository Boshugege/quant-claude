### 0.2 指标与口径（全文通用）

- **五项指标**：IC（截面 Spearman 秩相关均值）、IC_IR（逐截面 IC 均值 ÷ 标准差）、多空夏普（前 10% 减后 10%，下文简称「多空」）、压力稳定性（按截面标签离散度分两半、取较弱一半的 IC_IR，下文简称「压力」）、换手（多空两腿在**同一交易日内**相邻截面的替换比例，跨日不计）。本地表格统一写成「IC／IC_IR／多空／压力／换手」（定义见〔交接〕§1.2、〔R12〕§二）。
- **本地五项都是「平台口径」**：官方标签 + 10 个官方风格与 32 个申万一级行业剔除 + 与交付相同的 1.0 倍输出中性化 + 09:30 置零（〔R12〕§二、§六；`e2e/scripts/cmp_runs.py` 默认参数）。
- **fold-A**：2020–2022 训练，2023 年验证，另外预测 2024 年，两年分别看（〔R15 §四〕）。本地所有样本外证据都来自 fold-A；交付用的全量模型训练到 2024 年底，没有本地样本外指标（〔提交记录〕E09 行括注）。
- **公榜分**：五项在端到端赛道全部有效提交中的百分位等权平均，会随别人的提交漂移；**只有同一时刻快照里的配对差可比**，五项原始值不随快照变（〔提交记录〕10-14 快照段、E07b 行）。
- **编号**：E = 正式提交包（通常 2020–24 全量训练、多成员）；P = 公榜探针（通常 fold-A 单模型、种子 42，用来做同训练区间同种子的成对比较）；F = 全量训练的单成员 run；S、R、G、H、T、A、C、M = fold-A 本地实验臂。交付过的包不再修改，改动发新编号（〔提交记录〕文件头；〔记忆:e2e-delivery-format〕）。

### 0.3 两个赛道的关系（先说清楚，全文按此口径）

- **隔离的是输出与因子值**：端到端模型的输入里没有因子赛道的任何因子值、因子输出或因子 notebook 的计算结果；因子代码里也没有端到端模型的预测。2026-10-19 用户叫停过一次把端到端预测混进因子 1617 的诊断，此后两个方向都没有再混过（〔记忆:tracks-never-mix〕）。
- **研究思路是双向流动的**：E21 树成员的输入通道串是 `shape,book,book2,book3,tod,pos,state,cls,mkt,lead,dow,auc`（〔E21 权重〕`gbdt.cfg.win`），其中 pos（日内价格位置）、lead（领先滞后）、cls（尾盘习惯）、auc（收盘竞价）等是人工设计的通道，训练脚本注释写着它们「对应因子赛道 F 方向（1133、1200）」「对应 B 方向」（〔E21 训练脚本〕第 1320–1323 行）；输出中性化力度的注释写「参照因子 104 号」（第 65 行）。这些通道都在推理时由原始行情现场计算，不读取任何因子值。4 个 Transformer 成员和 2 个 GRU 成员只用 `shape,book,tod` 三组通道（〔E21 权重〕`win_groups`）。
- 10-15 我们曾自定「领先滞后等因子赛道设计过的公式属于灰色、不用」（〔R15 §一〕），10-25 起树成员（G8「全部通道」配置）启用了这些通道。这是早期自定规则后来发生的变化，正文第 4.9 节和第 8 节如实交代。

## 1. 一页总览

### 1.1 赛题一句话

端到端赛道要求在比赛平台上提交一个**可从零重训的模型**：读原始 1 分钟行情，在每个交易日的 8 个截面（09:30、10:00、10:30、11:00、11:30、13:30、14:00、14:30）给股票池里每只股票打一个分数，预测截面之后 30 分钟的「收盘价 ÷ 窗口 VWAP − 1」；平台按五项指标在全部提交中的百分位等权打分（〔交接〕§1；〔R12〕§一）。公榜用提交的权重直接推理，私榜阶段平台调用训练脚本从零重训，用于检查违规（〔R04〕R4、R12）。

### 1.3 E21 一句话

**E21 = 4 个 Transformer 成员 + 2 个 GRU 成员（同一套「三尺度专家 + 同伴注意力 + 融合头」网络，只换 1 分钟序列编码器）+ 1 个 800 棵树的梯度提升成员；各成员逐截面排名后平均（树占七分之一），再对 4 个行情风格特征做 1.0 倍截面中性化、09:30 截面输出常数 0。训练目标是「截面秩 → 正态分位数」，辅以多周期辅助目标、多任务辅助头和只在训练时起作用的腿换手损失，训练标签对行情代理与伪行业取残差；所有输入都在推理时由原始行情现场计算。**（〔E21 权重〕`member_cfgs`、`gru_members`、`gbdt`；〔E21 训练脚本〕`e04_predict_range`、第 1246–1314 行常量；〔详解〕§1）

## 2. 赛题与平台合同

### 2.1 提交物：三个固定文件

官方 demo 规定提交三个平铺在同一目录的文件（〔交接〕§1.1；〔R04〕R10；主办方官方 demo 脚本，未收入公开仓库）：

| 文件 | 作用 | 要求 |
|---|---|---|
| `Transformer_modelsave_train.py` | 训练脚本，同时是训练与推理共用定义的「单一事实来源」：配置常量、模型结构、数据构建、`train_and_save`、JSON 存取 | 文件名必须固定（推理 notebook 用 `from Transformer_modelsave_train import ...` 导入） |
| `Transformer_modelsave_predict.ipynb` | 推理 notebook，只有 `main(datasources, start_date, end_date)` | 平台只替换数据源与起止日期后调用 |
| `transformer_model.json` | 权重 | **必须是文本格式（JSON）、不超过 50 MB**（主办方官方 demo 脚本 第 1 行）；demo 把每个张量存成 `{dtype, shape, data}` |

- demo 的默认配置：10 个原始字段（开高低收、量、额、买一价、卖一价、买一量、卖一量），每个截面回看 64 根 1 分钟 bar，`d_model=64, nhead=4, nlayers=2, dim_ff=128`，5 轮、batch 512、学习率 1e-3、种子 42，只训练 2020 年、最多 200 只股票（主办方官方 demo 脚本；〔内部记录〕「现有 demo 的关键限制」）。
- 输出三列 `date / instrument / factor`（〔E21 训练脚本〕推理路径；`e2e/scripts/verify_package.py` 断言列名）。早期说明里出现过 `score`，最终按 demo 与平台实测用 `factor`（〔内部记录〕；〔记忆:e2e-transformer-status〕）。

### 2.5 私榜重训：规则、我们的准备与不确定性

- 规则：私榜阶段平台调用 `train_and_save` 从零重训，「用于检查违规（如未来数据）」；「评分以提交的模型为主」；超时或报错会联系选手（〔R04〕R4、R12；〔交接〕§1.3）。项目记忆里两种说法并存（「私榜在平台上用 train_and_save 重训」与「评分仍以提交的模型为主，重训用于检查违规」），私榜分到底来自提交权重还是重训模型，**未记录**（〔记忆:e2e-transformer-status〕；〔记忆:competition-rule-updates-2026-10〕）。

- 需要说明的两点（〔交接〕§3.2；〔E21 训练脚本〕第 97、181 行；各 run 的 `config.json`）：
  1. 冻结权重是本地训练的，训练标签读的是由 1 分钟数据重建的 `labels_y_off.parquet`（与官方截面秩相关约 0.97）；私榜重训走 `DaiBackend.labels`，直接读官方标签表 `cpt_jyc_2026_vwap.vwap_return`。

### 2.6 评分口径（与本地评估一一对应）

出处：〔交接〕§1.2；〔R12〕§二、§六；`e2e/src/metrics.py` 文档串。

1. 平台先做因子处理：inf 处理 → 去极值 → 标准化 → 对当日 10 个风格因子（SIZE、BETA、MOMENTUM、RESVOL、SIZENL、BTOP、LIQUIDTY、EARNYILD、GROWTH、LEVERAGE）**加 32 个申万一级行业哑变量**回归取残差。主办方曾说「不剔除行业」，平台探测证明实际剔除了行业：加行业后与平台处理后的因子值相关 1.000000，不加行业只有 0.93–0.97（〔R12〕§六第 2 条）。
2. IC 用残差因子与标签的截面 Spearman；IC_IR 不年化。
3. 多空夏普按每年 242 × 8 个截面年化。
4. 压力 = 按截面标签离散度分高低两组，取较弱一组的 IC_IR（E01 自测反推：低波动 IC_IR 约 1.06、高波动约 0.866，报告值 0.8657，〔R06〕第 2 条）。
5. 换手只计同一交易日内相邻截面，跨日不计（按此定义本地与平台的误差从 0.023 降到 0.002，〔R12〕§二）。
6. **常数截面不计 IC、不计换手**（被跳过，而不是记为 IC = 0）。这条后来成为「09:30 截面输出常数 0」这一推理杠杆的依据（〔R14〕S1；〔E21 训练脚本〕`zero_0930` 文档串）。
7. 基准收益 10-10 改为股票池每个截面的平均收益，所有分数清零重算（E01 由 0.34909 变为 0.33857）；对排序类指标没有影响（〔R04〕R1；〔提交记录〕E01 行）。
8. 公榜总分 = 五项在所有参赛提交中的名次百分位等权平均，别人提交越强，同样的原始值排名越低（〔提交记录〕E13 节）。

### 2.8 两个「EMA」不能混

- **输出 EMA 平滑（已撤回）**：10-10 我们试过对每只股票的预测按时间做指数平滑，本地 α=0.5 时换手降 34%、IC +7%（旧标签口径，数值已作废）；但它直接违反 R3「推理时不可以使用自己对上一个截面的输出」，当天撤回、删除代码（〔R03〕表与更新说明；〔R04〕R3；〔R12〕§五）。
- **权重 EMA（10-17 起采用）**：训练时对模型参数做滑动平均（`E04_WEIGHT_EMA = 0.995`），保存和推理都只用平均后的权重，推理不接触任何历史输出。作用是把种子噪声减半（第 4.7 节）（〔R15 §二十〕；〔E21 训练脚本〕第 1276、2277、2452–2456 行）。
- 这条区分决定了端到端降换手的全部手段只能放在训练侧（多周期辅助目标、腿换手损失、权重 EMA、集成），这是第 6.2 节「换手定价」一节的前提。

### 3.3 「一份脚本、两种后端」

基础设施的核心设计（〔记忆:e2e-transformer-status〕「How to apply」；`e2e/scripts/train_local.py` 文件头）：

- `e2e/submission/Transformer_modelsave_train.py` 是唯一事实来源，平台走 `DaiBackend`（用 SQL 查平台表），本地走 `FeatherBackend`（读 feather，接口相同）。
- 本地训练入口 `e2e/scripts/train_local.py`（430 行）只做三件事：解析命令行参数（共 85 个 `add_argument`）后改写模块常量；把数据构建换成带缓存的版本；挂上逐轮验证与训练后自检的回调，然后调用**同一个** `train_and_save`。平台上两个回调为空，代码路径与私榜重训相同。
- 参数分组覆盖了整个实验史：数据与区间（`--train`、`--val`、`--norm`、`--extra-times`、`--year-w`、`--day-bag`）；结构（`--arch`、`--fuse`、`--win-groups`、`--tod-route`、`--patch-len`、`--seq-enc` 等）；目标与损失（`--target`、`--train-neutral`、`--aux-w`、`--mtl-w`、`--listnet-w`、`--turn-w`、`--pair-units`、`--leg-turn`、`--leg-tau` 等）；优化（`--epochs`、`--lr`、`--seed`、`--weight-ema`、`--sam-rho` 等）；推理后处理（`--out-neutral`、`--zero-0930`、`--daily-mix`）；运维（`--resume`、`--measure`）。
- 训练后自检（每次都做）：JSON 重新加载，在训练设备和 CPU 上分别重建模型，对前 2 万个验证样本比较预测最大差（E21 成员：Transformer 1.0e-3、GRU 3.0e-3，见 F40、F70 日志）；检查 JSON < 50 MB；再用推理入口 `predict_range` 对整个验证区间重新预测并与训练路径比对。e04 结构下这一比对的 `maxdiff` 常常不为 0（F40 为 1.86e-01，匹配 487,456／488,000 行），一个可能的解释是两条路径的截面成员不完全相同、而截面排名和同伴注意力依赖同截面的其他股票，**这个解释没有专门核实**（〔run:F40_2020-24_E18_leg01_s42〕`log.txt`）。

### 3.4 平台 SQL 与本地的等价性

1. **30 分钟窗口与 09:30 缺陷（10-11）**：窗口类输入（日内、日线、同伴、风格特征）都来自 30 分钟窗口表，平台执行 `_WIN30_SQL`（回看 130 天），本地读 30 分钟文件。我们发现因子赛道沿用的窗口 SQL 用「时刻 = 窗口终点」取末价，而 1 分钟数据在 09:25 竞价 bar 之后直接是 09:31，**09:30 窗口末价永远缺失**；平台导出证实因子 90、104 在 09:30 截面 100% 输出 0。端到端 E04 包用的是同一段 SQL，平台推理时 09:30 输入与本地训练不一致。修复为 09:30 窗口取 09:25 竞价 bar 的价格；用 DuckDB 0.9.2（推断与平台同代）在本地 1 分钟数据上原样执行，修复后与本地 30 分钟窗口表末价、成交额 100% 一致（〔R12〕§三；`e2e/scripts/sql_win30_check.py`）。
2. **窗口 SQL 扩展（10-12）**：新增原始成交额、成交笔数 100% 一致；窗口收盘 99.96%；开高低在 10:00 以后 100% 一致，只有 09:30 竞价窗口不一致，所以形态特征不用 09:30 窗口（〔R14〕「窗口 SQL 扩展核对」）。
3. **盘口窗口（10-13，E08 起）**：平台用 `_BOOK30_SQL` 查 1 分钟表；本地用同一段 SQL 在本地 1 分钟数据上预先算好缓存（`e2e/scripts/build_book30_cache.py`），两边逐行核对最大差 1e-7（〔R14〕S7；〔提交记录〕E08 行）。
4. **收盘集合竞价（10-23）**：`e2e/scripts/build_auc_cache.py` 同样用 DuckDB 执行 `_AUC_SQL` 生成逐月缓存（〔R15〕R32 节）。
5. **模拟平台 `e2e/scripts/fake_dai/`**：只支持提交代码用到的几类查询，底层读 feather；10-11 起窗口 SQL 用 DuckDB 真正执行（之前走本地 30 分钟文件，所以没拦住 09:30 缺陷）；读暴露表直接抛错；读标签表返回本地重建标签（〔R12〕§三末条）。

### 3.5 标签缓存：官方定义、一次推翻与本地重建

- **官方定义（10-11 平台探测核实）**：`vwap_return = end_price / vwap − 1`，窗口是截面之后的 30 分钟 (t, t+30]；两段导出 100% 吻合、误差小于 1e-7；11:30 截面对应 13:01–13:30，14:30 截面对应 14:31–15:00、同日有标签。含义是「截面之后 30 分钟内按 VWAP 买入、窗口结束按收盘价卖出」（〔R12〕§一）。
- **之前用错了**：10-11 之前本地用 `y_v2v1`（下一窗口 VWAP 买、再下一窗口 VWAP 卖），是用因子榜公榜分反推出来的，与官方截面秩相关只有 0.56，且 14:30 缺失；「E01 本地 IC 0.0547、平台 0.0550」的吻合是巧合（按时段拆开，旧标签与平台各时段 IC 的相关只有 0.40，官方口径 0.94）。旧标签代码与缓存全部删除，报告 01–08、10 加更正说明（〔R12〕§一、§五）。这次推翻起于 10 月 11 日上午用户的质疑：此前「VWAP 延后 30 分钟」的标签判断可能并不成立。当时 Claude 仍认为旧标签是对的，随后写平台探测脚本由用户在平台运行，结果推翻了旧结论（〔R12〕）。
- **本地重建**（`feather_data.make_labels`）：把 1 分钟 bar 分到 9 个桶，窗口 VWAP = 成交额和 ÷ 成交量和，分钟成交均价须在 [最低价 × 0.98, 最高价 × 1.02] 内才参与（官方 VWAP 也做了类似清洗：不清洗的 VWAP 在含异常分钟的窗口里偏离官方 7 倍以上，按此规则清洗后中位相对差约 1e-4）（〔R12〕§二）。
- **精度**：与官方截面秩相关约 0.97，按窗口看 0.94–1.0（〔交接〕§3.2；〔R12〕§一）。
- **缓存**：`e2e/scripts/build_label_cache.py` 一次生成 2020-01～2024-12 全部截面的标签，写 `e2e/cache/labels_y_off.parquet`（约 2 分钟）；本地训练与评分优先读它（〔交接〕§3.2）。缓存行数**未记录**。

### 3.6 本地评测与平台对齐（为什么本地数字可信）

### 4.0 读法

### 4.2 诊断探针 P01 与新结构「多尺度专家 + 同伴注意力」（E04，10-11）

**P01 诊断**：把因子 104 的平台代码原样塞进端到端 notebook（训练脚本是占位，没有可训练参数），只用来区分 H1／H2（判据：约 0.8 → H1，约 0.4 → H2），是诊断探针，不是比赛成绩，也不参与选型。公榜 0.73571，远高于同期 E03 0.42286，更接近 H1（〔提交记录〕P01 行；〔R08〕§5）。

**一次合规刹车**：P01 出分后，Claude 建议「以因子 104 为底，再让神经网络做有限的补充」；10 月 11 日上午，用户先询问规则是否允许以传统因子为基底，随后以合规风险为由否决了这条路线，决定采用更稳妥的做法，并要求先设计神经网络、用简单的语言说明后再动手。P01 从此只作诊断，不作正式成绩；当时主办方有一条「买卖量不平衡不允许」的答复，新网络也先把不平衡类特征去掉（〔R11〕）。

**E04 结构**（〔R11〕第一节；〔详解〕§4）：

- 三个尺度专家：短线专家看最近 64 根 1 分钟 bar × 10 个原始字段（2 层 Transformer）；日内专家看最近 18 个 30 分钟窗口（1 层）；日线专家看之前 20 个交易日（1 层）。
- 同伴画像：每只股票过去 60 日的收益序列经一个小 MLP 编码成 32 维画像。
- **同伴注意力**：在同一截面内，按画像相似度对其他股票的专家表示做注意力加权，得到「同伴背景」，每个专家的输出变成「[自己的表示, 自己 − 同伴背景]」，即只看相对同伴的偏离。直觉（推断）：把同行业、同主题、同风格的共同部分减掉，打分更依赖个股相对同伴的异常，这与评测「剔除风格和行业后再排序」的口径一致。
- E04 的三个专家各自打分、截面排名等权合成；训练标签对 10 个官方风格取残差，损失 = MSE + (1 − 风格剔除后截面相关)；推理 1.5 倍中性化；2 种子 × 3 轮。

**结果**：E04 公榜 0.35491。原因很快查明（下一节）：训练用了旧的错误标签，窗口 SQL 在 09:30 取不到末价；交付记录写「不建议提交」，但当时包已经上传（〔R12〕第四节）。

### 4.4 合规版 E07：行情代理 + 伪行业，09:30 置零（10-12）

**S0：代理能补上多少官方风格**（〔R14〕S0，2023）：行情代理 + 伪行业解释官方风格的平均截面 R²：BETA 0.79、RESVOL 0.73、LIQUIDTY 0.69、MOMENTUM 0.64、BTOP 0.54、SIZE 0.44、GROWTH 0.17、行业 0.24；伪行业与申万一级的调整兰德指数 0.31。结论：量价类风格大部分能补上，规模和财务类补不全。

**S1：只改推理**（同一份 E06A 预测，没有种子噪声）：**09:30 截面输出常数 0** 后，2023 IC 0.0872 → 0.0923、IC_IR 1.741 → 1.875、压力 1.595 → 1.793、换手 0.583 → 0.547，2024 同向；中性化每 +0.5 倍 IC 约 −0.003，1.0 倍最好（〔R14〕S1）。机理：平台跳过常数截面，而 09:30 是最弱的截面（跨日窗口、竞价价格），把它置零等于让平台只评其余 7 个截面（〔R14〕S1；第 2.6 节第 6 条）。

**E07 做法**：①训练不再读官方暴露表，标签和损失改为对**行情代理特征**（成交额规模及其平方、波动、beta、非流动性、20/120 日动量、相对放量、低价，均只用前一交易日及更早）+ **伪行业**（每月初用过去 120 个交易日超额日收益做球面 k-means，30 类）逐截面取残差；②09:30 截面输出常数 0；③1.0 倍中性化；2 种子 × 3 轮。

**本地**（同配置 G3 单种子）：2023：0.091／1.83／54.5／1.72／0.61；2024：0.076／1.19／40.4／1.11／0.61。

### 4.10 腿换手损失（P17–P22、E18、E18g，10-25～10-27）

**动机**：

**机制**（〔E21 训练脚本〕`_e04_train_one` 第 2303 行 `_pair_units` 与第 2399–2428 行；〔信号质量〕§7.2）：
1. `PAIR_UNITS = True`：每个训练单元是同一交易日的两个相邻截面（按轮次交替配对），批内仍跨日随机。
2. 每个截面上取模型的合成分，先对风格暴露做残差（「评分机按残差排名定腿」），再标准化。
3. 用不回传梯度的排序取 90% 与 10% 分位数作腿边界，软腿成员 = sigmoid((x − 边界) ÷ τ)，τ = 0.15。
4. 对两个截面都出现的股票（≥ 20 只），损失加上 λ × 平均[(多头软成员之差)² + (空头软成员之差)²]，λ = `E04_LEG_TURN`。只在腿边界附近有梯度——只惩罚「进出多空腿」的那部分变动，而不是全部排名变动。
5. **推理时完全不用**：每个截面独立预测，不读模型之前的输出。项目记忆的原话是「腿换手损失是合规的杠杆，因为模型不能用自己之前的输出」（〔记忆:e2e-transformer-status〕10-26 段）。

| 35 | **跨赛道混合**（两个方向都只做过只推理诊断） | 10-16、10-19 | 因子输出混进端到端：「不作交付」；端到端预测混进因子 1617：用户否决，脚本作废 | 〔R15 §十六〕；〔记忆:tracks-never-mix〕 |

从这张表能读出三条规律（第 6 节展开）：
1. 「拿 IC_IR、多空、压力换换手」的做法（换手惩罚、少训一轮、日线锚、头部混合、腿换手 0.3 以上、E22）在端到端公榜上几乎全部不划算；只有不伤这三项的降换手（多周期辅助目标、权重 EMA、种子集成、腿换手 0.1、GRU 成员）被采用。
2. 「当日分钟细节」类改动（全天 patch、同时段 token、14:30 尾盘习惯、中间时刻成员）本地涨、公榜不涨或反向。
3. 网络结构类改动几乎全部否决，唯一成立的结构是融合头与当前时段；真正的增量来自监督信号（秩目标、多周期、多任务、腿换手）和成员多样性（树、GRU）。

### 6.2 对「换手定价」的认识

端到端的特殊处境：规则不允许推理时使用自己上一截面的输出，因子赛道常用的「缓冲带」「平滑」在这里都不能用，**降换手只能放在训练侧**。我们对公榜如何给换手定价的认识，是一步步被公榜纠正出来的：

1. **10-12～10-14：以为可以照搬因子榜的价格**。P03（少训一轮，换手 −0.036）和 P06（换手惩罚，换手 −0.10）都掉分 → 「端到端榜不为用 IC 换换手付钱」（〔提交记录〕10-14 快照、P06 行）。
2. **10-15 晚**：全榜排名分半天内整体掉了 0.05～0.09（原始五项没变），掉得最少的是换手最低、压力最高的 P06 → 「换手和压力在排名里的相对分量变大」（〔提交记录〕10-15 晚快照）。
3. **10-17**：E12 → E13 的 +0.044 主要来自换手 −0.025、压力 +0.019 → 「每降 0.01 换手都值钱」；**降方差的改动在公榜兑现得比本地更多**（〔提交记录〕E13 小分段）。
4. **10-18～19**：P12（日线锚，换手 −0.040 但 IC_IR −0.041、多空 −2.2）仍掉分；P13 换手 +0.028 却 +0.054 → 换手的价远低于 IC_IR／压力（〔R15 §二十九〕；〔提交记录〕P13 节）。
5. **10-23**：P16 换手 −0.030、IC +0.002 → +0.017（〔提交记录〕P16 节）。
6. **10-26**：P17 换手 −0.036、IC −0.0015 → 同页 +0.020；五个同快照点给出的粗略价格「换手 −0.01 ≈ +0.004，IC +0.001 ≈ +0.0012」（欠定，只在换手 0.51～0.56 这一段适用）；**但 P18／P19 崩盘**：0.3 起 IC_IR −0.2、压力 −0.14 掉出对手密集区（〔提交记录〕10-26 段、P18／P19 段）。
7. **归纳**：端到端榜在我们所处的位置（换手 0.51～0.56）对手很密，换手是「在不伤 IC_IR、压力、多空的前提下」最有弹性的一项；一旦这三项掉出密集区，换手再低也救不回来。腿换手 0.1 恰好落在这个窗口里（E18g 约 +0.03）。

### 6.3 集成的收益来自信息差异，而不是成员个数

这条认识也是分几步形成的：

1. **种子噪声（10-17）**：同配方不同种子的预测相关只有 0.878／0.871，约 12% 的排名差异来自种子；公榜给「降方差」的价远高于本地（E12 → E13 公榜 +0.044，本地只有很小的 IC 增益）（〔R15 §十九〕；〔提交记录〕E13）。
2. **权重 EMA 是便宜的集成（10-17）**：种子相关提到 0.94，EMA 双种子集成 ≈ 原双种子集成，再堆同类种子收益变小（〔R15 §二十〕）。
3. **训练方式不同的成员（10-21～23）**：时段成员与底座相关约 0.90，混合对优于同类两种子（〔R15 §二十一〕）；按交易日抽样的成员更多样但更弱，抵消（R16／R17）；「3 个底座 + 3 个多任务 = 6 个」不比 3 个多任务好，而「3 个普通 + 3 个中间时刻」两年 IC +0.002——提升来自多样性，不是成员数（〔R15〕「集成规模」「输出形式与集成多样性」）。
4. **不同的信息（10-24～25）**：树成员直接在原始三档盘口字段上分裂，补上了 Transformer 因 rel2 归一化学不出的「每笔挂单规模」类信息；与 Transformer 截面秩相关约 0.76（〔R15〕「树模型成员」；〔提交记录〕E21 行）。
5. **不同的模型族（10-27～28）**：GRU 成员与 Transformer 相关约 0.90，单独略弱但换手更低，进集成换手单调下降（第 4.11 节）。
6. **反例**：最不相关的「细视角树」（相关约 0.51）因换手 +0.019 抵消收益，没有进交付；MLP 成员、慢视角树伤 IC_IR 与压力。

归纳：**成员要尽量保持满强度，同时看到不同的信息或有不同的归纳偏置**；只换种子或只少给数据得到的多样性不够，「越不相关越好」也不成立。这一条与用户 10-27 提出的「为不同的信息选用高效的结构」方向一致，也是 E21 的最后一块拼图。

## 7. 私榜选择：为什么是 E21，而不是 E22（以及 E20、E18g）

### 7.1 规则背景

- 私榜只在各队**最终勾选**的作品之间排名；端到端每队只有 **1 个位置**（因子 2 个）；别队的五项原始值看不到；公榜 10-29 关闭、勾选 10-30 截止（〔记忆:private-board-selection〕，用户 10-26 重申）。

### 7.4 为什么是 E21

把仓库记录与当时的检查合起来，选 E21 的理由有五条：

1. **公榜同页最高**：10-28 同一页面 E21 0.91551 对 E18g 0.91023（〔提交记录〕「E21 公榜」节）。
2. **不是交换来的分**：相对 E18g 只有换手 −0.006，IC +0.0001、IC_IR −0.008、多空 +0.19、压力 +0.002，四项持平；与 fold-A 预期（两年换手 −0.008、其余持平）一致；四个半年同向；GRU 个数 0 → 1 → 2 → 4 换手单调下降（剂量反应）。换手又是本地 → 公榜最可靠的一项（不计任一侧为 0 的配对，19／20 同向）。
3. **每个组成部分都过了「fold-A → 公榜」闸门**：秩目标（P13）、6 轮 + 多任务头（P16）、腿换手 0.1（P17）、树成员（E17b − E16 同页 +0.0022；P22）、GRU 成员（E21 − E18g 同页）。
4. **合规证据完整**：截断检测 0 差异；推理不用模型之前的输出；腿换手损失只在训练时作用；训练脚本写死区间、种子与成员分工。
5. **备选的问题**：E20 的机制（中间时刻成员）在 P23 公榜上方向相反，用户决定不交；E22 在本地每个半年都是「IC_IR 换换手」，正是记忆里写的「turnover-traded」方向，用户担心对着公榜过拟合、始终没有上传。

仓库里没有一条单独写明「为何不选 E22」的文字记录（〔提交记录〕E22 节写的是「与 E21 同页比，取高者」，但 E22 从未上传）；上面第 5 条来自内部记录与项目记忆，属于当时决定的复述。最终私榜候选为 E21（〔指南〕开头）。

## 8. 结果复盘与主线梳理

### 8.1 我们做对了什么

1. **先对齐口径，再谈模型**。头两天最大的收益不是来自网络，而是来自「把本地和平台对齐」：官方标签核实（旧标签与官方秩相关只有 0.56）、评测剔除含 32 个行业、换手只计同日、09:30 窗口 SQL 缺陷与常数截面被跳过。E05 → E07 的 +0.154 主要来自 09:30 置零这一个推理端改动（〔R12〕；〔R14〕）。
2. **训练目标对齐评测口径**。秩 → 正态分位数目标是整场最大的单点模型改进（P13 对 P10 +0.054，单个 fold-A 模型超过四种子 E13），理由很朴素：评测 IC 是秩相关（〔R15〕R2；〔提交记录〕P13）。
3. **承认结构不是答案**。10-20 用户要求探索真正能让网络训练变强的结构，我们认真试了一轮（注意力池化、跨尺度注意力、SAM、市场门控、加深），全部否决，并把结论写下来：「提升来自监督信号，不来自结构」。之后的增量都来自监督信号与成员多样性（〔R15〕第 1089 行）。
4. **在规则约束下找到降换手的合法杠杆**。不能用自己之前的输出，就把降换手放进训练：多周期辅助目标、权重 EMA、种子集成、腿换手损失、GRU 成员；并用 P16–P19 画出公榜的换手价格曲线，把 λ 定在 0.1（〔提交记录〕P18／P19 节）。
5. **三级闸门 + 事先写判据**。E15、E16 的开工条件都在看分之前写定；E14、E20、E22 都因为没过闸门而不交（第 6.1 节）。
6. **最后一步选择不追公榜**。E22 在本地每个半年都是「IC_IR 换换手」，没有上传；私榜选五项最稳的 E21（第 7 节）。
7. **合规可审计**。截断检测脚本、`package.py` 的禁表断言、模拟平台读暴露表即报错、训练／推理分离、写死区间与种子，都是可复跑的代码而不是口头承诺（第 3.10 节）。

### 8.3 开发历程的七条主线

**主线一：从 0.34 到 0.81——先对齐口径，再谈模型（10-10～10-12）**

不逐日整理，只说怎么分工、怎么转起来。正式的说明见 `文档/决赛材料/提交材料/端到端赛道/端到端赛道_AI工具使用说明.pdf`。

- **一轮工作怎样转起来**（10-18 起定型）：Claude 提出一轮实验的几个臂和理由，用户确认后开跑（10-12 起用户要求先报规划、确认后再动手）→ fold-A 单种子跑、与同机对照比两年五项 → 累积到本质提升才打包一个公榜探针、用户上传 → 探针确认后才做全量多成员训练 → verify、截断检测通过后交给用户。
