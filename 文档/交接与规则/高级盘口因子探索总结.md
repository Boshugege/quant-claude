因此下一步的核心不应是继续试探 `0.2/0.4/0.6` 这样的档位权重，而应构造：

1. 每个档位自己的标准化不平衡；
2. 跨档方向的一致性、离散度和稳健聚合；
3. 对极端值的概率化或饱和变换；
4. 完整 30 分钟内的稳定性，而不是简单追逐最后几分钟。

## 二、从高级微观结构研究中真正可迁移的部分

- [Queue Imbalance as a One-Tick-Ahead Price Predictor](https://arxiv.org/abs/1512.03492)：队列不平衡与下一次中间价方向存在显著关系；作者还发现局部 logistic 拟合略优于单一线性 logistic。可迁移启发是：不要只使用线性不平衡，应尝试概率化、饱和化和局部状态映射。
- [Multi-Level Order-Flow Imbalance in a Limit Order Book](https://arxiv.org/abs/1907.06230)：多层 OFI 的样本外解释力随纳入价位层数增加而提升。可迁移启发是：五档应视作一个向量，研究跨层结构，而不是只挑第五档。
- [The Price Impact of Order Book Events](https://arxiv.org/abs/1011.6402)：短时间价格变化主要由订单流不平衡驱动，冲击斜率与市场深度反向相关。可迁移启发是：如果未来确认价格和事件字段，应构造 OFI/深度归一化，而非只看静态挂单量。
- [Cross-Impact of Order Flow Imbalance in Equity Markets](https://arxiv.org/abs/2112.13213)：多层 OFI 的整合变量优于只看最优价，滞后跨股票 OFI 对未来收益有额外解释力。当前比赛暂时没有可靠的跨股票实时特征接口，因此先保留为后续方向。
- [DeepLOB](https://arxiv.org/abs/1808.03668)：卷积提取盘口空间结构，LSTM 提取时间依赖，并且在不同股票间有一定迁移性。当前平台不适合直接训练深度网络，但可以手工提取“空间模式 + 时间稳定性”的低维代理变量。
- [Queue-reactive Hawkes models for the order flow](https://arxiv.org/abs/1901.08938)：订单流同时受当前队列状态和过去事件影响；市场单与中间价变化率主要依赖不平衡，限价单和撤单的到达率则更复杂。当前只有 1 分钟快照量，不能假装拥有事件级 Hawkes 数据，但可以研究快照层面的稳定性和异常压力。

## 三、下一批最想尝试的五个因子

下面五个都可以先只用已经确认的十个字段实现，暂时不依赖价格、成交量或外部网络。它们不是简单的已有因子改名，而是分别对应稳健统计、概率映射、稳定性和跨层交互。

### 1. 五档逐档不平衡的中位数/截尾均值

令每个档位的标准化不平衡为：

```text
z_i = (bid_volume_i - ask_volume_i)
      / (bid_volume_i + ask_volume_i + ε)
```

15 使用的是 `mean(z_1, ..., z_5)`，已经达到 0.31033。下一步不再改变档位权重，而是用五个 `z_i` 的中位数，或去掉最大值和最小值后的截尾均值。

经济含义：如果某一档存在异常挂单、数据尖峰或短暂伪装，均值会被拉动，中位数和截尾均值可以保留多数档位的共同方向。

优先级：**最高**。这是对当前最强结果最直接、风险最小的稳健化。

### 2. 全五档一致性门控的标准化不平衡

先算：

```text
m = mean(z_i)
spread = mean(abs(z_i - m))
coherence = max(0, 1 - spread)
factor = m * coherence
```

16 只对买四、买五做一致性门控，得分 0.29890。新版本把门控扩展到全部五档，但不使用原始挂单量作为权重。

经济含义：共同方向的盘口压力比单档极端值更可信；当五档互相矛盾时，降低该分钟信号，而不是直接让它主导 30 分钟均值。

优先级：**最高**。它直接结合 15 和 16 的两个强证据。

### 3. 逐档 logistic / tanh 概率化不平衡

对每档做饱和映射：

```text
p_i = 2 / (1 + exp(-k * z_i)) - 1
factor = mean(p_i)
```

其中 `k` 可先固定为 1.5 或 2.0，不做大网格搜索。

经济含义：队列不平衡研究使用 logistic 概率模型；极端不平衡不应线性地无限增加边际预测力。这个因子保留每档方向，但把极端值压缩到有限区间。

优先级：**高**。21 的保符号幂变换已经达到 0.29363，说明非线性变换值得继续，但概率化比固定幂指数更有微观结构解释。

### 4. 30 分钟“方向稳定性调整”的逐档共识

先得到每分钟的逐档平均 `m_t`，再在 SQL 中同时聚合：

```text
mean_m = mean(m_t)
second = mean(m_t * m_t)
stability = mean_m / sqrt(second + ε)
```

也可以用 `mean_m / (mean(abs(m_t)) + ε)` 作为更稳健版本。

经济含义：同样的平均不平衡，如果 30 分钟内频繁正负切换，可信度应低于持续同向的盘口。它不追逐末段，也不假设方向趋势，只区分“稳定压力”和“抵消后的平均值”。

优先级：**高**。20 的半窗趋势只有 0.04088，说明方向变化本身不是好信号；但这不等于稳定性无效，二者要区分。

### 5. 跨档符号一致的“软交集”因子

设 `z_i` 为逐档不平衡，定义：

```text
sign_consensus = sign(mean(z_i))
strength = min(abs(z_i))
factor = sign_consensus * strength
```

或者只在至少四档同向时保留 `mean(z_i)`，否则衰减为 0。

经济含义：它寻找“整本盘口都同向”的状态。与 15 的平均不同，某个方向只有在多数档位都支持时才有较大输出，适合过滤单层 spoofing 或孤立异常。

优先级：**中高**。它可能比一致性门控更稀疏，若信号覆盖率下降，需要重点检查每个截面的缺失率。

## 四、暂时明确放弃的方向

- 原始远档权重继续微调：07、12、01 已经形成窄平台，继续调权重容易过拟合公榜。
- 原始深度重心、层间斜率、侧内尾部占比：13、14、17 都接近 0.05，当前方向假设不成立。
- 半窗趋势、末段窗口：20 和 03 都弱，目标更像完整窗口的状态变量，而不是窗口内斜率。
- 总深度或成交量加权：05、11 均下降，规模本身不是可靠权重。
- 直接照搬 DeepLOB/Hawkes：当前平台只允许因子函数和聚合，不能在提交代码里训练深度模型或拟合事件级点过程；应先提取低维结构代理。

## 五、真正可能打开上限的字段方向

## 七、字段确认后新增的五个高级候选（22–26）

用户已经确认分钟表同时提供五档价格、五档委托量、五档委托笔数，以及 `high`、`low`、`amount`、`volume`。因此本批代码把研究从“只有挂单量的不平衡”扩展到价格—深度—成交的联合状态。每个因子都仍然只在逐分钟 UDF 中计算信号，再在 SQL 中做 30 分钟平均，没有读取未来分钟。

### 22｜多层微价格位移

对每一档用对侧队列做交叉加权：

```text
micro = Σ_i (ask_price_i × bid_volume_i + bid_price_i × ask_volume_i)
        / Σ_i (bid_volume_i + ask_volume_i)
factor = (micro - (ask_price_1 + bid_price_1)/2) / spread_1
```

它把“买方深度更多会把隐含成交价推向卖价、卖方深度更多会把隐含成交价推向买价”的队列机制推广到五档，并用一档价差消除不同股票价格尺度。与 15 的区别是，15 只输出无量纲队列不平衡，22 还利用了每档价格位置。

### 23｜价格距离加权深度凸性

将买档和卖档分别按其距离一档中间价的倒数加权：

```text
effective_bid = Σ_i bid_volume_i / (mid - bid_price_i + spread_1)
effective_ask = Σ_i ask_volume_i / (ask_price_i - mid + spread_1)
factor = (effective_bid - effective_ask) / (effective_bid + effective_ask)
```

它刻画的是“有效可成交深度”而不是原始挂单总量：离中间价近的队列对短期价格冲击更敏感，远档的量则按实际价格距离折扣。与 01、12 的固定档位权重不同，23 会随每只股票的真实价差和档位间距变化。

### 24｜委托笔数不平衡

```text
factor = (Σ_i bid_num_orders_i - Σ_i ask_num_orders_i)
         / (Σ_i bid_num_orders_i + Σ_i ask_num_orders_i)
```

同样的挂单量可能由一笔大单或许多小单组成。24 使用队列广度来区分这两类状态，提供一条与挂单量正交的信号。它不把委托笔数当作成交量权重，因此不会复用已被 05 结果否定的总深度加权逻辑。

### 25｜平均委托单大小不对称

先分别计算两侧每笔委托的平均挂单量，再取有界对数比：

```text
bid_size = Σ_i bid_volume_i / Σ_i bid_num_orders_i
ask_size = Σ_i ask_volume_i / Σ_i ask_num_orders_i
factor = tanh(log((bid_size + ε) / (ask_size + ε)))
```

24 衡量的是“有多少笔”，25 衡量的是“每笔有多大”。两者可以区分广泛的小单排队、少量大单支撑和少量大单压盘等不同队列形态；`tanh(log ratio)` 让极端大单不会把截面排序完全锁死。

### 26｜微价格与成交 VWAP 背离

用 22 的多层 microprice 与当前分钟成交 VWAP 比较：

```text
trade_vwap = amount / volume
factor = tanh((micro - trade_vwap) / max(high - low, spread_1))
```

这是盘口隐含价格和已实现成交价格的跨源背离。若盘口隐含价格持续高于成交 VWAP，可能表示买方队列压力尚未完全反映到成交；反向则可能表示卖方压力。它直接使用了比赛目标中的 VWAP 相关字段，与纯盘口不平衡因子形成正交补充。
